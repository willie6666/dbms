11. 心得 (每個人的心酸血淚史)

這次做這個 DBMS 專案真的滿累的。一開始在規劃遊戲商店平台 VaporAuror 的時候，我以為只要把資料庫的表建好，然後照著寫 API 就沒事了。結果到了專案後期，才發現比較麻煩的是要把說明文件跟實際的程式碼對齊。

我在一開始寫了很多業務邏輯的文件，像是購物車結帳，退款流程，還有管理員刪除評論之類的功能。後來跟後端 Go 程式碼和最初的 api spec 比對，才發現我寫太多沒有做的東西。像是文件裡寫了錢包餘額扣款，還有管理員隱藏評論，但其實當初畫 mermaid 圖和寫 db 初始化腳本的時候，根本沒有設計這些功能跟欄位。我只好又花很多時間，回頭去把業務邏輯文件裡面多寫的東西一行一行刪掉。一直改來改去，處理文件跟程式碼的問題花了不少時間。

但最麻煩的還不是改 Code，是我的電腦硬碟空間。在趕專案的這幾天，C 槽的空間莫名其妙急速下降，直接少了 20 幾 GB，整個硬碟進度條變成紅色。我一開始還以為是編輯器吃掉的，或是中毒，找了很久的原因。後來查了老半天，才知道是 Docker 佔用的。每次在那邊 docker compose build 測試的時候，Docker 留下了很多舊映像檔和快取。而且 Windows 的 WSL 虛擬硬碟，就算我下了 prune 指令刪掉 Docker 的資料，它也不會自動把空間還給我。

我最後只好去開命令提示字元，先把 wsl 強制關機，然後用 diskpart 指令，去選取那個二十幾 GB 的 vhdx 檔案壓縮它，才終於把我的 20 GB 救回來。看到硬碟空間回來的那一刻，我才鬆了一口氣，不然我連存檔都快存不了。

總結來說，這次專案除了學到怎麼寫後端 API 和設定資料庫，最大的體會就是寫文件不要寫太多沒有把握做出來的功能，不然到最後收尾會很痛苦。還有用 Docker 要隨時注意硬碟空間，不然電腦容量會不夠。雖然過程遇到不少問題，但最後看到整個遊戲商店跑起來，也算是有學到東西。
